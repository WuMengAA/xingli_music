## 批次 A：LOD 重构（Distant Horizons 风格体素 LOD）+ 飞行修复

### A1–A3 诊断（为什么现在是「平面」+「幽灵方块」）

现状链路（voxel_renderer.dart）：
- `_buildLodCell`(2383)：step=2 采样 g×g 高度网格 `hGrid/vGrid`（g=size/2）→ `topY=max(hGrid)`、`majority` 单色、5 代表列 samples、4 邻条带 nTop/sTop/wTop/eTop（2435-2440）、relief 高度场（rs=size<=4?4:6，2442）。
- `_emitLodCell`(2576)：**只发顶面**（size<=8 分 4 块、远档单色 samples[4]）+ 4 条边界裙边（邻顶更低才露）+ relief 崖面（相邻 relief 高差>1 处）。
- `_emitLodQuad`(2700)：单面投影 + 背面剔除 + `_colorOf` 上色。

**根因 ①「平面不是大方块」**：单元内 g×g 采样被**拍平为一块顶面**——内部列高信息（hGrid）只用来取 max，丢失全部内部几何 → 远看是平面马赛克，不是体素方块堆叠。

**根因 ②「只有单色」**：侧边裙边/崖面一律用 `cell.majority`（2449 起）；远档顶面用 samples[4] 单色。内部列的真实方块颜色（vGrid）被丢弃。

**根因 ③「高山侧面空/幽灵方块」**：内部峰顶周围无侧面几何（relief 只在相邻采样高差>1 处发面，且 rs=6 对 size=8/16 与 step=2 不对齐）→ 侧看空心；孤立高峰的顶面浮空、下方无实体 → 幽灵。

**根因 ④「云层上方幽灵方块」**：`_emitClouds` 在 `b.eyeY >= cloudY-1.0` 直接 return（1541），但 LOD 顶面不受影响 → 飞到云上后，高海拔地形/顶面平板仍在 → 云上方漂浮幽灵方块。

**根因 ⑤「地下幽灵方块」**：地下未封闭（S3 未触发）时 LOD 照发顶面；顶面在头顶上方很远处，透过洞口/缝隙可见 → 幽灵；relief 崖面在洞穴里也可能出现游离竖面。

### A1–A3 设计：DH 风格「逐列立方体」发射

Distant Horizons 核心：LOD 单元不是一张平面，而是**分辨率降低的体素列**——每列 = 一个立方体（顶面 + 暴露侧面），按该列真实方块上色 → 块状地形剪影、侧壁实心、多色。

**`_buildLodCell` 改造**（相机无关，继续走缓存）：
1. 保留 g×g 主网格（g=size/2，step=2）——`hGrid/vGrid` 已含全部所需信息，**无需新增采样成本**。
2. 新增 **外环 1 格**采样：(g+2)×(g+2) 网格 `hExt/vExt`，外环=单元外侧 step=2 对齐采样（取代 4 条带 nTop/sTop/wTop/eTop + 统一边界逻辑）。成本 O(4·size/2) 列，可忽略。
3. relief 删除（其职能被逐列侧面完全覆盖）；`majority/5 samples` 保留仅用于「平坦快路径」。
4. 缓存键不变（(tier, gci, gcj)），`_LodCell` 字段改为持有 `hGrid/vGrid`（或 (g+2)² 扩展网格）+ topY + displayTopY + majority + 平坦标志。

**`_emitLodCell` 改造**：逐列发射（所有内部列 + 边界列）：
- **顶面**：每列一个顶面 quad，`vGrid[k]` 上色（多色）。平坦快路径：若全部列等高且同色 → 退化为单顶面 + 4 边界裙边（当前行为，平原零开销）。
- **侧面**：每列 4 条边，若邻列（含外环）高度 < 本列 → 发竖直接面，从邻高到本列顶，`vGrid[k]` 上色、法线指向较低侧（复用 `_emitLodQuad` 背面剔除自动隐藏内侧）。
- 效果：山峰=逐列台阶剪影（块状、DH 味）、侧壁实心（无空心/幽灵）、云上只有真峰露出（无漂浮平板）、地下无游离面（S2 可见集照常过滤）。
- 保持：geomorph（displayTopY 缓动）、迟滞、视锥剔除、budget 分帧、S2 visible 过滤——全部复用。

**面数预估**：逐列顶面 = (size/2)²/单元。远档 cell=32 → 256 顶面/单元，比现状多 ~256×；但远景单元数少 + 视锥剔除减半 + 平坦快路径 + 侧背面剔除 → 总量可控。若实测超标，加「同高同色连续列 RLE 合并顶面」优化（后续）。

**幽灵方块专项**：
- 顶面不再整体抬到 max → 云上漂浮平板消失（只余真峰）。
- 山体侧面实心 → 高山侧面空/幽灵消失。
- 地下：S2 可见集 + 逐列实体侧壁 → 无游离幽灵面。

### A4 飞行修复（合并上一条反馈「飞行上升一顿一顿」「狭小空间起飞卡住」）

**根因 ①上升一顿一顿**（voxel_world_view3d.dart 1120-1131）：垂直上升扫描 `double top = _fpPos.y; for (yy=y+0.2; yy<=ny; yy+=0.2){ if(_bodyCollides) break; top=yy; } ny=top;` —— 无碰撞时 `ny` 被**量化到 0.2 整数倍**，自由飞行上升每帧都 0.2 一跳 → 顿挫。
- 修：`top = ny`（请求值）起步，仅在真碰撞处回卷 → 自由上升平滑，顶头仍停。

**根因 ②狭小空间起飞卡住**（1679-1709 `_onJumpButtonDown`）：双击起飞强制 `_held.add(_Nav.up)`（1693）→ 顶头时每帧 `ny=y+lift` 被碰撞夹回 y，MTV 推出又与墙互顶 → 卡死。
- 修：起飞瞬间先查净空 `!_bodyCollides(_fpPos.x, _fpPos.y+0.2, _fpPos.z, bodyH)`，有净空才续接上升；无净空 → 平飞（不强制上升），允许横向滑出（MTV 已提供推出）。
- 顺带：`_fpVy=0` 恒定（飞行）保持；下降触地退飞（1154）保持。

## 批次 B：人物 / 物理 / 模式统一

### B1 骨骼绑定身体、跟随朝向
- 现状：头跟随视线（已有）；身体/骨骼未对齐移动方向/视线。
- 设计：玩家模型渲染处（voxel_world_view3d.dart 模型绘制）——身体 yaw 朝**移动方向**（MC 语义），头部 yaw/pitch 跟随视线；站立不动时身体回正到视线 yaw（lerp 平滑）。骨骼为纯绘制层，不改物理。

### B2 跳跃「单一处理」改 AABB 分轴解算（根治跳一半撞方块卡住）
- 现状：水平移动先判 `baseY` 与 `baseY+1`（assistStep 仅空中），垂直上升扫描遇头即 `_fpVy=0` 停；若水平同时被挡 → 空中卡死。
- 设计：每帧按 MC 分轴：① X 轴平移+碰撞；② Z 轴平移+碰撞；③ 垂直（上升扫描初始化 top=ny + 1 格台阶辅助）——头被挡仅停垂直，水平仍可滑动/绕行。
- 新增**地面 1 格台阶自动上步**：`_fpOnGround` 且水平被 1 高台阶挡、抬 1 格净空 → 自动踏上（=「不在边缘也能跳上 1 格」；原 `_autoJump` 开关合并为默认上步 + 可关）。

### B3 生存/创造逻辑统一（跳跃高度一致 + 创造可蹲 + 创造=「许可飞行」）
- 统一跳跃：两模式同一 `jumpVelocity = sqrt(2*g*jumpHeight)` + 同一重力积分路径（当前生存 1082-1095 与创造 1098-1116 已同式，核对差异来源——疑似创造 `_fpJumpQueued` 被 `_onJumpButtonDown` 双击窗口吞掉；修：单击跳跃与双击飞行的判定解耦）。
- 蹲：`_Nav.down` 语义 = 蹲（`_crouching`）当 `_survival || !_flyMode`；= 飞行下降当 `_flyMode`（MC 一致；当前创造 Shift 恒下降 1758-1768 → 改）。
- 飞行 = 创造专属**许可**（`!_survival` 才可 `_flyMode`），与跳跃高度无关。

- 现状：破坏/放置目标块射线从相机出发（TP 下相机在身后/侧位 → 射线穿过障碍物破坏墙后方块）。
- 设计：目标块射线统一从**玩家眼位 + 玩家 lookDir** 出发（与 FP 一致）；相机仅负责渲染视角。准心 UI 居中（look 与相机 yaw 一致时即角色看向）；TP 下即使相机被墙遮挡，破坏/放置仍以角色视线为准（不穿墙）。

## 批次 D：渲染剔除修复 + 环境光遮蔽

### D1 特定角度剔除当前区块
- 现状：`_chunkInFrustum`(voxel_camera.dart)/`_cellInFrustum`(renderer 2823) 8 角视锥判定；S5 已有 `camInChunk` 永不剔。
- 排查：陡俯/陡仰时相机所在区块 8 角是否全在近平面外 → 误剔。修：相机所在区块（及其 3×3 邻）加膨胀/强制保留（恢复 S5 前逻辑的精简版：`inflate` 内圈 3×3 永不剔）。

### D2 低视距（<2）正前方一刀切
- 现状：buildFrame 方阵按 `maxDist`（含 viewDistanceChunks*16）裁 → 视距低时正前方覆盖不足。
- 修：**总覆盖半径与视距解耦**：`coverageChunks = ceil(far/frustumHalfAngle)+1`（至少满足当前视锥），视距只控制「满精度带 vs LOD」切换，LOD 环永远补到视锥远平面外。保证任何视距下正前方无硬切。

### D3 向下 90° 剔除脚下两格以下
- 排查：`projectWith` 近平面（viewZ<near 丢弃）在正俯视时把脚下近柱剔除，或 `_cellInFrustum` yMin=0 判定。
- 修：正俯/正仰时对**眼柱及相邻 8 柱**强制保留（类似 camInChunk 的近柱白名单）；近平面 clip（S1）已保面级正确，区块级再加近柱白名单。

### D4 环境光遮蔽（低性能高效果）
- 设计：MC 式**面级 AO**，在**全精度区块构建期**计算并烘焙进面顶点色（零运行时成本）：
  - 对每个面角点，AO = 该角相邻 2 侧边方块 + 1 对角方块（3 采样）遮挡加权（经典 MC AO 0.2/0.4/0.6 档）。
  - 面 tint 乘 AO 系数；LOD 单元不做 AO（远景体素天然够）。
  - 缓存：随 ChunkMesh 构建一次性完成，`_colorOf` 之外新增 `faceAo` 通道（顶点色乘）。
- 效果：墙角/洞穴口自然压暗，立体感大增，性能 ≈ 0。

## 批次 F：控制方案

- **F1 触屏**：滑动=视角（保留）；方块交互 = 专属 UI 按钮 或 **长按=破坏（连击）、双击=放置**（在 3D 视图 GestureDetector 加 onLongPressStart/onDoubleTap，射线用 C 批次角色视线）。
