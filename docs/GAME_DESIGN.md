# 游戏设计文档（GDD）：Flutter 复刻《我的世界》

> **文档说明**：本文档参考了专业的游戏设计文档（GDD）模板结构，并结合了 Flutter 生态中已有的实现案例。目标是为 AI 辅助开发提供一份清晰、完整、可拆解的“施工图纸”。


## 一、核心玩法循环（Core Gameplay Loop）

这是游戏最基本的体验闭环，所有系统都围绕它运转：

```
探索世界 → 采集资源 → 合成工具 → 建造/战斗 → 探索更深/更远 → (循环)
```

玩家的核心行为分为三个层次：
- **探索**：移动、观察、发现新地形、生物群系和结构
- **创造**：采集、合成、建造、改造环境
- **生存**：维持生命和饥饿、战斗、应对环境和敌对生物

> **AI 协作提示**：将以上每个箭头（→）拆解为独立的 AI 任务，逐个实现并测试。


## 二、世界生成系统（World Generation）

### 2.1 区块系统（Chunk System）

世界被划分为固定大小的立方体区域进行管理。

| 参数 | 值 | 说明 |
|------|-----|------|
| 区块大小 | 16 × 16 × 256 方块 | 水平 16×16，垂直 256 格 |
| 加载范围 | 视距半径（如 8 区块） | 只加载玩家周围的区块 |
| 存储结构 | 三维数组 `[16][16][256]` | 每个元素存储方块类型 ID |

### 2.2 地形生成算法

**种子（Seed）**：一个整数，作为所有随机数生成器的起点，确保相同种子生成相同世界。

**多层 Perlin 噪声叠加**（分形布朗运动，fBm）：

```
最终高度 = 噪声1(频率1) × 振幅1 + 噪声2(频率2) × 振幅2 + 噪声3(频率3) × 振幅3 + ...
```

| 层数 | 频率 | 振幅 | 作用 |
|------|------|------|------|
| 第1层（低频） | 低 | 大 | 决定大陆/海洋的宏观轮廓 |
| 第2层（中频） | 中 | 中 | 添加丘陵、山谷等地形起伏 |
| 第3层（高频） | 高 | 小 | 增加地表细节（小凸起、凹陷） |

**生成流程**：

```
种子 → 噪声生成高度图 → 判定生物群系 → 放置地表方块 → 生成结构（树木、洞穴等）
```

### 2.3 生物群系（Biomes）

不同区域拥有不同的地形特征、方块组成和植被。

| 生物群系 | 地表方块 | 植被 | 地形特征 |
|----------|---------|------|---------|
| 平原 | 草方块 | 少量树木、花 | 平坦开阔 |
| 森林 | 草方块 | 大量橡树/白桦 | 起伏较小 |
| 沙漠 | 沙 | 无 | 平坦，有沙丘 |
| 山地 | 石头/草 | 少量松树 | 高度落差大 |

### 2.4 三维密度噪声（可选进阶）

Minecraft 实际使用的是**三维密度噪声**（在 XZ 平面采样地形高度，在 Y 轴采样方块存在概率），可生成悬空地形和洞穴。

### 2.5 光照系统

- **天空光照**：随时间变化（昼夜循环），垂直向下衰减
- **方块光照**：火把、熔岩等光源向周围传播，亮度逐格递减

> **AI 协作提示**：先实现“平坦世界 + 手动放置方块”，再逐步叠加噪声地形和光照。


## 三、玩家系统（Player System）

### 3.1 移动与物理

| 属性 | 说明 |
|------|------|
| 移动速度 | 步行 ~4.3 m/s，疾跑 ~5.6 m/s |
| 跳跃高度 | ~1.25 格（带重力加速度） |
| 重力 | 恒定向下加速度（~32 m/s²） |
| 碰撞箱 | 宽 0.6 格，高 1.8 格（玩家实体） |
| 流体影响 | 在水中减速、可游泳；在熔岩中受伤 |

**碰撞检测**：检测玩家 AABB（轴对齐包围盒）与周围方块的碰撞箱是否重叠。

### 3.2 视角控制

- **第一人称**：相机位于玩家眼部高度（~1.6 格）
- **第三人称**：相机位于玩家后方，需做**碰撞检测**避免穿模
- **鼠标/触控**：控制视角俯仰和偏航

### 3.3 生存属性

| 属性 | 范围 | 说明 |
|------|------|------|
| 生命值（Health） | 0–20（10颗心） | 归零则死亡 |
| 饥饿值（Hunger） | 0–20（10个鸡腿） | 随时间消耗，过低时无法疾跑 |
| 经验值（Experience） | 整数 | 通过采矿、杀敌、烧炼获得 |

**死亡与重生**：生命值归零时显示死亡画面，在出生点或最后睡过的床旁重生。

### 3.4 HUD（平视显示器）

- 生命值、饥饿值、经验值条
- 快捷物品栏（9格）
- 准星（屏幕中央）
- 手持物品名称

> **AI 协作提示**：先实现“自由飞行相机 + 无重力移动”，再逐步添加重力、碰撞和生存属性。


## 四、交互系统（Interaction System）

### 4.1 射线检测（Raycasting）

从屏幕中心发射一条射线，检测与场景中方块的交点。

**用途**：
- **选取目标方块**：确定玩家“看向”的是哪个方块
- **确定放置位置**：在目标方块的相邻面放置新方块
- **攻击实体**：检测是否指向生物

**检测流程**：
```
1. 从相机位置沿视线方向发射射线
2. 遍历射线路径上的体素（Voxel Traversal）
3. 遇到第一个非空气方块 → 返回该方块位置和相交面
4. 如超出最大距离（~5格）→ 无目标
```

### 4.2 破坏方块

| 参数 | 说明 |
|------|------|
| 挖掘速度 | 取决于方块硬度和玩家手持工具 |
| 掉落物 | 方块被破坏后掉落对应的物品实体 |
| 动画 | 方块表面出现裂纹纹理（破坏进度） |

**公式**（简化）：
```
挖掘时间 = 方块硬度 × 30 / 工具倍率
```

| 工具 | 倍率 | 适用方块 |
|------|------|---------|
| 徒手/错误工具 | 1.0 | 所有方块（极慢） |
| 木镐 | 2.0 | 石头类 |
| 石镐 | 4.0 | 石头类 |
| 铁镐 | 6.0 | 石头类 |
| 钻石镐 | 8.0 | 石头类 |
| 斧头 | 1.5–8.0 | 木质方块 |
| 锹 | 1.5–? | 泥土、沙等 |

### 4.3 放置方块

- 在射线检测到的**相邻面**放置新方块
- 需检查目标位置是否已被占用
- 放置后触发方块更新（如影响光照、触发红石）

### 4.4 与实体交互

- **攻击**：对生物造成伤害（取决于武器）
- **使用**：右键/交互键触发（如打开门、喂食动物、点燃 TNT）

> **AI 协作提示**：先实现“射线检测 + 高亮目标方块 + 点击放置/破坏（瞬秒）”，再逐步添加工具倍率、硬度和动画。


## 五、内容系统（Content System）

### 5.1 方块系统（Block System）

每个方块由以下属性定义：

```json
{
  "id": "minecraft:stone",
  "hardness": 1.5,          // 硬度（影响挖掘时间）
  "blast_resistance": 6.0,  // 爆炸抗性
  "transparent": false,     // 是否透明（影响光照和渲染）
  "render_type": "solid",   // solid / transparent / fluid
  "collision": true,        // 是否有碰撞箱
  "texture": {              // 纹理映射（六面或图集索引）
    "top": "stone_top",
    "bottom": "stone_bottom",
    "side": "stone_side"
  },
  "drop": "minecraft:cobblestone"  // 破坏后掉落物
}
```

**方块状态（Block State）**：同一类型方块的不同变体（如不同朝向的木头、不同充能等级的红石线）。

### 5.2 物品系统（Item System）

```json
{
  "id": "minecraft:iron_pickaxe",
  "type": "tool",
  "max_stack": 1,           // 最大堆叠数
  "durability": 250,        // 耐久度
  "mining_speed": 6.0,      // 挖掘倍率
  "attack_damage": 4,       // 攻击伤害
  "texture": "iron_pickaxe"
}
```

**物品分类**：
- 基础材料（木头、石头、铁锭、钻石）
- 工具（镐、斧、锹、锄、剑）
- 武器（剑、弓、箭）
- 食物（面包、牛排、苹果）
- 装饰（楼梯、 slabs、栅栏）
- 红石元件（红石粉、中继器、比较器）

### 5.3 背包系统（Inventory System）

| 特性 | 说明 |
|------|------|
| 存储空间 | 36格（9×4）+ 9格快捷栏 |
| 堆叠 | 同种物品可堆叠（最大64或16或1） |
| 拖拽/点击 | 支持左键、右键、Shift+点击等操作 |
| 持久化 | 使用 Hive 等方案保存玩家数据 |

### 5.4 合成系统（Crafting System）

**有序合成（Shaped Crafting）**：
```
  pattern: ["WWW", "W W", "WWW"]  // W = 任意木板
  key: { "W": "minecraft:planks" }
  result: { "id": "minecraft:chest", "count": 1 }
```

**无序合成（Shapeless Crafting）**：
```
  ingredients: ["minecraft:melon", "minecraft:melon", ...]
  result: { "id": "minecraft:melon_seeds", "count": 1 }
```

**配方类型**：
| 类型 | 适用方块 | 说明 |
|------|---------|------|
| 工作台有序 | 工作台 | 3×3 网格，需按图案摆放 |
| 工作台无序 | 工作台 | 3×3 网格，任意摆放 |
| 熔炉 | 熔炉 | 燃料 + 材料 → 成品 |
| 切石机 | 切石机 | 石材 → 石质装饰品 |
| 锻造台 | 锻造台 | 工具 + 材料 → 升级工具 |

### 5.5 生物与 AI 系统（Mobs & AI）

**AI 意向（AI Goal）系统**：每个生物有一组按优先级排序的行为目标。

| 优先级 | 行为（Goal） | 触发条件 |
|--------|-------------|---------|
| 最高 | 攻击玩家 | 玩家在视野/感知范围内 |
| 中 | 追逐目标 | 目标在追踪范围内 |
| 低 | 随机巡逻 | 空闲状态 |
| 最低 |  idle | 默认 |

**基础生物类型**：

| 生物 | 生命值 | 行为 | 掉落物 |
|------|--------|------|--------|
| 僵尸 | 20 | 夜间生成，追逐玩家 | 腐肉、稀有掉落 |
| 骷髅 | 20 | 夜间生成，远程射箭 | 骨头、箭 |
| 蜘蛛 | 16 | 夜间生成，主动攻击 | 线、蜘蛛眼 |
| 苦力怕 | 20 | 夜间生成，接近玩家后爆炸 | 火药 |
| 牛 | 10 | 被动，漫游 | 皮革、生牛肉 |
| 羊 | 8 | 被动，漫游 | 羊毛、生羊肉 |
| 鸡 | 4 | 被动，漫游 | 羽毛、生鸡肉 |

### 5.6 数据驱动设计（Data-Driven Design）

所有游戏内容通过 **JSON 文件**定义，而非硬编码在代码中：

| 数据类型 | 目录 | 示例 |
|----------|------|------|
| 方块定义 | `blocks/` | `stone.json` |
| 物品定义 | `items/` | `iron_pickaxe.json` |
| 配方 | `recipes/` | `chest.json` |
| 生物定义 | `entities/` | `zombie.json` |
| 战利品表 | `loot_tables/` | `zombie.json` |
| 生物群系 | `biomes/` | `plains.json` |

**优势**：
- 内容与代码分离，便于调整和扩展
- 非程序员（策划、美术）可独立修改游戏内容
- 支持热更新和 Mod 加载

> **AI 协作提示**：先硬编码少量方块和物品验证核心机制，稳定后再迁移为 JSON 数据驱动。


## 六、渲染与性能优化（Rendering & Optimization）

### 6.1 渲染优化技术

| 技术 | 说明 | 参考 |
|------|------|------|
| **背面剔除（Back-face Culling）** | GPU 自动跳过背对相机的三角面 |  |
| **面剔除（Face Culling）** | 只渲染暴露在空气或透明方块外的面 |  |
| **顶点缓存（Vertex Caching）** | 每个区块的顶点数据缓存复用，无需每帧重建 |  |
| **实例化渲染（Instancing）** | 相同方块的多个实例合并为一次 Draw Call |  |
| **LOD（Level of Detail）** | 远处区块使用简化模型 |  |
| **空间裁剪（Frustum Culling）** | 只渲染视锥体内的区块 |  |
| **BVH 空间索引** | 加速射线检测和可见性判断 |  |

### 6.2 渲染流程

```
Flutter 展示层 (SceneView)
    ↓
场景逻辑层 (Scene, Node, Camera)
    ↓
渲染数据层 (RenderItem, BVH)
    ↓
渲染调度层 (RenderGraph, RenderPass)
    ↓
绘制编码层 (SceneEncoder, Material)
    ↓
GPU 后端层 (Flutter GPU / Impeller / WebGL2)
```

### 6.3 flutter_scene 技术栈优势

- **PBR 材质**：基于物理的渲染，光照真实
- **glTF 模型导入**：支持 .glb 格式
- **环境贴图/IBL**：基于图像的光照
- **阴影、SSAO、SSR**：高级后期效果
- **物理引擎集成**：Rapier、Box3D 后端
- **动画混合**：骨骼动画支持
- **3D 场景中的 Flutter Widget**：UI 与 3D 场景混合

> **AI 协作提示**：初期只关注“面剔除 + 顶点缓存”，其他优化可后续迭代。

> **项目注记（xingli_music 现状）**：本项目采用**自研软件光栅化渲染器**（非 flutter_scene GPU 管线），已落地 16×16 区块、Perlin fBm 无限地形、面剔除 + 背面剔除 + LOD + 区块几何缓存、第一/二/三人称相机 + 碰撞箱、射线检测破坏/放置、MC 多采样音效、AI 陪伴体素小人。详见 git 提交历史 R23d–R23t。


## 七、技术架构建议

### 7.1 分层架构

| 层级 | 职责 | 技术选型 |
|------|------|---------|
| **表现层（Presentation）** | 渲染、输入、音效 | `flutter_scene` |
| **游戏逻辑层（Game Logic）** | 世界状态、实体 AI、合成 | 纯 Dart，数据驱动 |
| **数据持久层（Persistence）** | 存档、设置 | Hive / SharedPreferences |
| **状态管理层（State Management）** | 全局游戏状态 | GetX / Provider |

### 7.2 游戏循环（Game Loop）

Flutter 应用使用 `Ticker` 驱动每帧更新：

```dart
// 每帧执行
void update(double deltaTime) {
    // 1. 更新玩家输入
    // 2. 更新物理（重力、碰撞）
    // 3. 更新 AI（生物行为）
    // 4. 更新世界（随机刻、方块更新）
    // 5. 更新相机位置
    // 6. 更新渲染（可见区块、LOD）
}
```

**刻（Tick）**：游戏逻辑的基本时间单位，理想状态下每秒 20 刻（每刻 50ms）。

### 7.3 状态管理

使用 GetX 或 Provider 管理全局状态：
- 玩家属性（生命、饥饿、位置、背包）
- 世界状态（已加载区块、时间）
- UI 状态（当前打开的界面、选中的快捷栏槽位）


## 八、开发路线图（分阶段交付）

### Phase 1: 技术验证（1-2 周）

**目标**：跑通 3D 渲染管线，显示一个带纹理的方块。

| 任务 | 验收标准 |
|------|---------|
| 搭建 Flutter master 环境，集成 `flutter_scene` | 应用能启动，无编译错误 |
| 创建一个带纹理的立方体 | 屏幕中央显示一个旋转的纹理方块 |
| 实现基础相机控制（旋转/平移） | 鼠标拖拽可旋转视角 |
| 实现“世界”概念（三维数组存储方块类型） | 能在一个网格中放置多种方块 |

### Phase 2: 核心世界（2-3 周）

**目标**：生成可探索的无限地形，实现第一人称移动。

| 任务 | 验收标准 |
|------|---------|
| 实现区块系统（16×16×256） | 世界按区块加载/卸载 |
| 实现 Perlin 噪声地形生成 | 启动游戏生成起伏的地形 |
| 实现面剔除优化 | 只渲染暴露面，帧率提升 |
| 实现第一人称相机（含重力、跳跃、碰撞） | WASD 移动，空格跳跃，有重力 |
| 实现基础生物群系（至少 2 种） | 不同区域地表方块不同 |

### Phase 3: 核心交互（2-3 周）

**目标**：玩家能破坏和放置方块。

| 任务 | 验收标准 |
|------|---------|
| 实现射线检测（选取方块） | 准星对准方块时高亮显示 |
| 实现方块破坏（左键） | 点击后方块消失，掉落物生成 |
| 实现方块放置（右键） | 在目标方块的相邻面生成新方块 |
| 实现不同方块的挖掘速度 | 石头比泥土挖得慢 |
| 实现顶点缓存优化 | 区块修改后重建缓存，而非每帧重建 |

### Phase 4: 玩法填充（3-4 周）

**目标**：加入生存要素、合成、背包和基础生物。

| 任务 | 验收标准 |
|------|---------|
| 实现背包系统（36格 + 9格快捷栏） | 按 E 打开背包，物品可拖拽 |
| 实现合成系统（工作台 3×3） | 按配方合成物品 |
| 实现生命和饥饿系统 | 显示生命/饥饿条，饥饿随时间消耗 |
| 实现昼夜循环 | 天空颜色和光照随时间变化 |
| 实现一种敌对生物（僵尸） | 僵尸在夜间生成，追逐玩家 |

### Phase 5: 打磨与扩展（持续）

**目标**：完善体验，扩展内容。

| 任务 | 验收标准 |
|------|---------|
| 实现第三人称视角（含碰撞检测） | 按 F5 切换视角，镜头不穿模 |
| 实现音效系统 | 行走、破坏、放置、生物音效 |
| 实现世界存档（Hive） | 退出游戏后世界状态保留 |
| 数据驱动重构 | 方块、物品、配方迁移为 JSON 定义 |
| 性能优化（LOD、实例化） | 大型世界稳定 60 FPS |


## 九、开发建议总结

1. **小步快跑，逐层递进**：每次只让 AI 解决一个明确定义的小任务，验证通过后再进行下一步
2. **维护设计文档**：将本文档作为 `GAME_DESIGN.md` 放在项目根目录，每次让 AI 写代码前先让它阅读
3. **版本控制是安全网**：每次 AI 修改前提交一次 Git，方便回滚
4. **数据驱动优先**：尽早将方块、物品、配方定义为 JSON，便于后期调整和扩展
5. **性能意识贯穿始终**：从 Phase 1 就考虑面剔除和缓存，避免后期重构
