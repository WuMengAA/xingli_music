# 星璃音乐 · 长期维护规范（MAINTENANCE）

> 配套文档：`docs/星璃音乐 · 构建手册.md`（构建操作）、`docs/服务状态与废弃内容盘点_YYYY-MM-DD.md`（存量盘点）。
> 本文档把散落各处的命名约定归纳为**一条制度**：**「命名即信息」**——
> 名称必须自解释（是什么・哪一版・什么时间・哪个渠道），禁止模糊命名。

---

## 1️⃣ 命名总则

一切**长期存在**的目录 / 文件 / 构建产物遵循五元组：

```
名称_版本_时间_渠道_编号
```

| 元组 | 要求 | 示例 |
|---|---|---|
| 名称 | 业务名，中文直用（星璃音乐） | `星璃音乐` |
| 版本 | `0.26.x`，「月」必**补零到 2 位** | `0.26.08.28` ✅ / `0.26.8.28` ❌ |
| 时间 | 日必补零到 2 位；日期统一 `YYYY.MM.DD` | `08.28` ✅ / `8.28` ❌ |
| 渠道 | beta / alpha / release，小写 | `beta` |
| 编号 | clNN（当天该渠道第几次构建，跨天清零） | `cl11` |

> ⚠️ **月/日补零是硬性要求**（对齐《构建手册》§2 的 `versionName` 约定，如 `0.26.08.19_alpha_cl01`）。
> 存量不合规命名**不追溯重命名**（改名会撕裂 sha256 配套与发布记录），仅在 §4 盘点。

## 2️⃣ 构建产物命名

产物一律落入 `release/`，格式：

```
星璃音乐_<版本>_<渠道>_cl<NN>[_{渠道_平台_别名}]_{arm32|arm64|win_portable}.{apk|zip}

星璃音乐_0.26.08.28_beta_cl11.arm64.apk
星璃音乐_0.26.08.28_beta_cl11.arm64.apk.sha256        ← 校验值同名前缀
星璃音乐_0.26.08.28_beta_cl11_pc_星尘初聚_win_portable.zip
```

配套规则：

- 每个产物必须带同名 `.sha256` 文件。
- versionCode **单调递增，永不清零**（见构建手册 §2）。
- 当日同渠道多次构建用 `clNN` 升序，跨天清零、日期更新。

## 3️⃣ 备份 / 快照 / 文档命名

| 类别 | 规则 | 示例 |
|---|---|---|
| 备份目录 | `backup/名称_YYYYMMDD[_说明]/`，**不用隐藏点号开头**；已废弃备份按盘点文档处置 | `backup/theme_migration_20260828/` |
| 盘点 / 周报 | `名称_YYYY-MM-DD.md` | `服务状态与废弃内容盘点_2026-08-30.md` |
| 通用文档 | `名称.md`（长标题用 `名称(二级).md`） | `PRD_UI_重构.md` |
| 草稿 | `_前缀.md`，稳定后去下划线 | `_draft_code_facts.md` |
| 已废弃 | 移入盘点文档登记 + 前缀 `已废弃_`，不就地删除 | `已废弃_XX方案.md` |
