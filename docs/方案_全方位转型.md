# 星璃音乐 · 全方位应用转型方案（博客 + 多功能服务聚合）

> 定位提案（用户 2026-08-31）：星璃从「音乐播放器」演进为「个人媒体中心 / 全方位应用」——既承载自有博客内容，又聚合既有功能与服务。
> 关联：`docs/白皮书自用精简总结_v3.md`（铁律）、`docs/文档体系总览.md`、`docs/方案_ClassIsland联动.md`。
> 状态：**v1.0 已拍板（2026-08-31）**——多栏目综合博客 + 小工具/网站聚合 + 液态玻璃组件替代方向；加仓订阅与服务端节奏均「先 MVP 后逐步上」。

---

## 1. 现状盘点：星璃已经是什么

「全方位」不是从零转型——星璃已具备 8 项可聚合能力：

| # | 能力 | 载体 | 状态 |
|---|---|---|---|
| 1 | 智能播放（本地策展 + 意境场景 + 刮削） | 播放核心 | ✅ 生产 |
| 2 | 网络电台（公开电台目录/直播流） | radio_source | ✅ 生产 |
| 3 | 电台房（校园广播 / 一起听 / 点歌，relay 中转） | 社交模块 | ✅ 生产 |
| 4 | 投屏（局域网 HTML 播放页 + Range 流） | cast_stream_server | ✅ 生产 |
| 5 | 自建 Subsonic 服务器接入 | music_source | ✅ 生产 |
| 6 | 自研 OTA（GitHub Release + Pages 双源） | ota_service | ✅ 生产（clOTA） |
| 7 | 本地状态服务（NowPlaying HTTP API） | now_playing_server | 🆕 本轮（ClassIsland 联动） |
| 8 | 体素世界 / 开放世界玩法 | world 模块 | ✅ 生产 |

「全方位」= 把 2~8 与**自有博客**统合成一个入口分明、能力自洽的应用，而不是堆功能。

## 2. 转型定位与边界（铁律兼容性分析）

白皮书 v3 三条铁律（对照）：

| 铁律 | 内容 | 转型兼容性分析 | 结论 |
|---|---|---|---|
| 铁律 1 | 不做社交评论 | 博客是**自有内容输出**（单向发布），不是 UGC 评论区；电台房是**同频共听**（私密房间），非公开广场。均不引入公开评论/关注/私信。 | ✅ 兼容 |
| 铁律 2 | 不做云端推荐 | 博客与聚合服务全部**本机/自建**；不接任何推荐 API、不上传播放行为做推荐。探索页的「推荐」是本地曲库规则引擎（已有）。 | ✅ 兼容 |
| 铁律 3 | 不搞第三方代理源 + 不玩 Hi-Fi 玄学 | 聚合的是**自有服务**（投屏/电台/网盘/OTA），不代理第三方音源；Hi-Fi 相关只做工程向（EQ/均衡器是工具，不贩卖玄学）。 | ✅ 兼容 |

**定位一句话**：**「星璃音乐」是用户自己的媒体中枢——内容（本地/自建）+ 同频（电台/投屏）+ 表达（博客）+ 服务（OTA/状态 API），全部自有、可控、可离线。**

明确不做（红线，写进 README 与设置页「关于」）：公开注册、评论/弹幕、云端曲库、付费订阅、第三方代理音源。

## 3. 形态设计：三入口收敛

保持现有「5 Tab」骨架，转型体现在**第一个 Tab（主页）**与**「星璃世界」入口**的重构：

```
主页（Today）
  ├─ 博客头条（新增：最近 3 篇自有文章标题，点击进博客）
  ├─ 场景音乐（现有）
  └─ 热门歌单 / 最近播放（现有）
功能页（现有 5 Tab：主页/探索/曲库/星璃世界/我的）
  └─ 星璃世界（扩展为「服务中心」聚合页）
       ├─ 电台房 · 点歌（现有）
       ├─ 投屏（现有）
       ├─ 博客（新增：博文列表 + 阅读页）
       ├─ 自建服务器 / 公开电台（现有）
       ├─ ClassIsland 联动（现有方案，设置里显示服务地址）
       └─ 软件更新（OTA，现有）
```

> 对外仍是一个「音乐 App」，博客与服务是**后台能力**——避免变成四不像。设置里统一入口叫「星璃中心」。

## 4. 博客子模块（M1）

> **拍板（2026-08-31）**：多栏目综合博客——非纯音乐主题，栏目按内容类型划分（音乐 / 随笔 / 工具 / 网站等），与「小工具/网站聚合」互为表里。

### 4.1 范围与铁律校验
- **单作者自有博客**：Markdown 文章 + 本地渲染（自有内容输出，无评论）。
- 文章目录：`<应用文档目录>/blog/`（Windows 与 Android 同构），支持 md 首部元信息（标题/日期/标签/**栏目**）。
- 栏目：文章首部元信息 `column` 字段（如 `music` / `essay` / `tool` / `web`），未指定 → 归入 `默认`；列表页提供栏目 Tab 过滤（横向滚动 chips）。
- 阅读页：内置 Markdown 渲染器（现有依赖中 flutter_markdown 若已引入则复用，否则不新增依赖，用最小渲染）。
- **不上传、不联网**：博客完全本地，符合离线/自建定位。

> 渲染引擎选型见 `博客子模块_技术选型对比.md`（推荐引入 `flutter_markdown`；是否新增依赖、导入导出形态随 §7 三问一并裁定）。

### 4.2 交付物
| 文件 | 内容 |
|---|---|
| `lib/pages/blog/blog_list_page.dart` | 文章列表（时间倒序，卡片 + **栏目 Tab 过滤** + 标签过滤） |
| `lib/pages/blog/blog_reader_page.dart` | 阅读页（标题 + 日期 + 栏目徽标 + 正文渲染） |
| `lib/services/blog/blog_store.dart` | 目录扫描 + md 解析（首部元信息，含栏目） |
| `test/services/blog_store_test.dart` | 解析单测（含栏目解析） |
| 设置页入口 | 设置→星璃中心→博客（仅启用后显示） |
| `assets/example_blog/` | 2 篇示例文章（**覆盖不同栏目**，引导用户放入自己的博客） |

### 4.3 与「文档体系」互不干扰
博客是**用户运行时内容**；仓库 `docs/` 是**开发治理文档**。两者物理分离（运行时文档目录 vs 仓库 docs/），仅共享「星璃中心」入口文案。

### 5.1 小工具 / 网站聚合（拍板新增方向）

用户拍板明确：**「全方位应用」应包含小工具与网站等能力**，与多栏目博客互为表里。聚合形态（均复用/最小实现，不越铁律红线）：

| 项 | 内容 | 红线校验 |
|---|---|---|
| 小工具抽屉 | 星璃世界/服务中心内「小工具」分组：文本转语音、颜色/Hex 转换、随机数、倒计时、简易计算器等纯本地小工具（首版选 2~3 个高频） | 纯本机，无联网，✅ |
| 网站收藏 / 聚合入口 | 个人常用网站的书签集合（本地存储），点开即经系统浏览器/内置 WebView 打开 | 不自建代理、不劫持，✅ |
| 后续（可选） | 自建小服务（如局域网状态面板）经同一中心入口呈现 | 随服务端节奏逐步上 |

> 小工具首版范围待实施时与博客 P1 合并排期；不放大本轮 P0/P1 工作量。

## 8. 液态玻璃组件替代（拍板新增方向）

现状：`lib/widgets/liquid_glass.dart` 已全量迁移到 `liquid_glass_widgets`（AdaptiveGlass 0.29.8，MIT）；`kNativeMinimal=true` 下 30 余处默认直通，仅 Dock/音乐控制栏等 forceGlass 白名单走真玻璃。

用户关注**替代方案**——评估点（待调研产出 `液态玻璃组件替代_调研.md`）：

1. 现依赖（liquid_glass_widgets）的维护活跃度、平台覆盖（Impeller/Skia/Web 回落路径）；
2. 备选：自研 FragmentShader（已有历史实现）、Flutter 官方 BackdropFilter 毛玻璃增强、其他 MIT 玻璃库；
3. 性能与稳定性权衡（已有 R32 图层隔离/RepaintBoundary 治理基础）；
4. 决策输出：保留 / 替换 / 双轨（Dock 用一、其余用另一）。

> 本节为调研项，结论落地前不动播放核心与白名单行为。
