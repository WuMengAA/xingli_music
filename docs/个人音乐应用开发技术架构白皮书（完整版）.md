class FileSystemManager {
  final Map<String, VirtualFileSystem> _mounts = {};
  
  void mount(String mountPoint, VirtualFileSystem fs) {
    _mounts[mountPoint] = fs;
  }
  
  VirtualFileSystem? resolve(String path) {

      if (path.startsWith(entry.key)) return entry.value;
    }
    return null;
  }

4.3.4 零拷贝切片响应
dart
Future<void> _handleStreamRequest(HttpRequest request) async {
  final path = base64Decode(request.uri.queryParameters['path']!);
  final file = File(path);
  final fileSize = await file.length();
  
  final rangeHeader = request.headers.value('range');
  final (range, _) = parseRange(rangeHeader, fileSize);
  
  int start = range?[0] ?? 0;
  int end = range?[1] ?? fileSize - 1;
  final isPartial = range != null;
  
  // 响应头设置
  final response = request.response;
  response.headers.add('accept-ranges', 'bytes');
  response.headers.add('content-type', 'audio/flac'); // 万能伪装
  response.headers.add('cache-control', 'no-cache');
  
  if (isPartial) {
    response.statusCode = HttpStatus.partialContent;
    response.headers.add('content-range', 'bytes $start-$end/$fileSize');
  } else {
    response.statusCode = HttpStatus.ok;
  }
  
  response.headers.add('content-length', '${end - start + 1}');
  
  // 分块推流（64KB 缓冲区）
  final raf = await file.open(mode: FileMode.read);
  await raf.setPosition(start);
  const chunkSize = 64 * 1024;
  int remaining = end - start + 1;
  
  try {
    while (remaining > 0) {
      final readSize = remaining > chunkSize ? chunkSize : remaining;
      final chunk = await raf.read(readSize);
      if (chunk.isEmpty) break;
      response.add(chunk);
      remaining -= chunk.length;
    }
  } catch (_) {
    // 音箱突然断开，静默关闭
  } finally {
    await raf.close();
    await response.close();
  }
}

4.4 播放状态协调器
4.4.1 设计目标
同一时刻只有一个输出端（本地扬声器/DLNA 音箱）拥有播放权

防止本地切歌导致投屏中断

防止投屏时媒体库文件被占用

4.4.2 核心代码
dart
class PlaybackCoordinator {
  static final PlaybackCoordinator _instance = PlaybackCoordinator._internal();
  factory PlaybackCoordinator() => _instance;
  
  enum ActiveOutput { none, local, dlna }
  
  final ValueNotifier<ActiveOutput> activeOutput = ValueNotifier(ActiveOutput.none);
  String? currentPlayingPath;
  final Map<String, int> _fileReadCount = {};
  
  /// 请求播放权限
  bool requestPlayback(String filePath, ActiveOutput requester) {
    if (activeOutput.value == ActiveOutput.none) {
      activeOutput.value = requester;
      currentPlayingPath = filePath;
      return true;
    }
    if (activeOutput.value == requester && currentPlayingPath == filePath) {
      return true;
    }
    // 冲突：强制剥夺旧输出
    _forceReleaseCurrent();
    activeOutput.value = requester;
    currentPlayingPath = filePath;
    return true;
  }
  
  void acquireFileLock(String path) => 
      _fileReadCount.update(path, (v) => v + 1, ifAbsent: () => 1);
      
  void releaseFileLock(String path) {
    if (_fileReadCount.containsKey(path)) {
      _fileReadCount[path] = _fileReadCount[path]! - 1;
      if (_fileReadCount[path] == 0) _fileReadCount.remove(path);
    }
  }
  
  bool isFileLocked(String path) => _fileReadCount.containsKey(path);
  
  void _forceReleaseCurrent() {
    // 通知 DLNA 断开、media_kit 停止
    activeOutput.value = ActiveOutput.none;
    currentPlayingPath = null;
  }
}
4.4.3 埋点位置
场景	调用方法
media_kit 切歌前	coordinator.isFileLocked(nextPath)
投屏服务器开始响应	coordinator.acquireFileLock(path)
投屏服务器响应结束	coordinator.releaseFileLock(path)
用户断开投屏	coordinator._forceReleaseCurrent()

4.5.2 文件指纹（防止数据搬家丢失）
指纹算法：文件大小 (size) + 文件头 1KB 的 MD5

dart
String computeFingerprint(File file) async {
  final size = await file.length();
  final header = await file.openRead(0, 1024).first;
  final md5 = md5.convert(header);
  return '${size}_${md5.toString()}';
}
数据迁移补偿：启动扫描时，若原 path 文件不存在，但有同 fingerprint 的其他路径记录，自动更新 path 字段

8. FAQ 与踩坑记录
Q1：media_kit 在 Android 12 以上后台解码失败？
原因：Android 12 限制后台应用 CPU 资源。

解决：使用前台服务通知，并在 AndroidManifest.xml 中声明 FOREGROUND_SERVICE_MEDIA_PLAYBACK 权限。

Q2：投屏时部分音箱播放几秒后自动停止？
原因：音箱检测到 HTTP 流没有持续的数据推送，或 Content-Length 不匹配。

解决：检查 Range 响应是否正确设置了 Content-Length，并确保分块推送没有提前关闭 response。

Q3：AirPlay 2 投屏到 HomePod 只有声音没有封面？
原因：AirPlay 2 的封面传输依赖 iTunes 特有的元数据格式。

解决：在 HTTP 响应头中添加 icy-metaint 元数据，或接受只有音频的事实（核心功能是听不是看）。

Q4：SQLite 数据库在大量写入时 UI 卡顿？
原因：主线程执行了耗时数据库操作。

解决：所有数据库写操作放在 compute() 或 Isolate 中执行，主线程只做读操作。

Q5：如何防止开发期手贱直接修改数据库？
方案：在 DatabaseHelper 构造时加入 isProduction 标志：

dart
class DatabaseHelper {
  final bool isProduction;
  
  Future<void> rawQuery(String sql) {
    if (!isProduction) {
      throw Exception('禁止在开发期直接执行 rawQuery，请使用 Repository 方法');
    }
    // ...
  }
}

# 第10章 沉浸式场景体验设计（视觉+音效+空间音频）

> **设计哲学**：让音乐不止于“听”，而是“住”进一个体素世界里。每一首歌都自带一个视觉场景，每一次播放都是一次空间漫游。

## 10.1 整体UI骨架（场景化播放器）

### 10.1.1 层级结构（从底到顶）
| 层级 | 内容 | 交互 |
|------|------|------|
| **背景层（Z=0）** | 全屏体素世界截图/循环视频（占满屏幕） | 不可点击，自动呼吸/微动 |
| **氛围光效层（Z=1）** | 动态光晕、粒子飘浮（叠加在背景之上） | 根据音乐节奏/音量变化 |
| **歌词浮动层（Z=2）** | Apple Music风格居中歌词（毛玻璃底衬） | 可上下滑动查看，点击切换“歌词/纯背景” |
| **控制层（Z=3）** | 底部播放栏、进度条、场景切换按钮（半透明磨砂玻璃） | 手势交互（上滑展开，下滑收起） |

### 10.1.2 首页入口（场景卡片墙）
- **不直接进播放器**，而是展示 **“场景卡片”** 瀑布流。
- 每张卡片 = **一个体素世界截图（动态缩略图） + 场景名称**（如“雨夜霓虹”、“森林木屋”、“太空站”）。
- 点击卡片 → 直接进入该场景的全屏播放器，并自动播放对应的“氛围歌单”（后续可手动切歌）。
- **视觉钩子**：卡片在滚动时有视差效果（3D倾斜），强化“体素世界”的立体感。

## 10.2 体素视觉系统（背景层 + 光效层）

### 10.2.1 资产类型（MVP阶段）
| 类型 | 格式 | 来源 | 适用场景 |
|------|------|------|----------|
| 体素世界静态截图 | 高清PNG（4K） | 使用MagicaVoxel或Blockbench预渲染 | 低性能设备、省电模式 |
| 体素世界循环视频 | MP4（H.265，循环无缝） | 预渲染导出（带轻微旋转/光影变化） | 默认推荐（沉浸感强） |
| 实时生成粒子 | Flutter CustomPaint / Rive | 代码生成 | 与音乐频谱联动 |

### 10.2.2 视频背景播放策略（技术实现）
- 使用 `video_player` 或 `media_kit` 的 `Player` 播放循环视频。
- **关键逻辑**：
  - 视频**静音**播放（只作为视觉背景）。
  - 切歌时**不重新加载视频**（预加载3个场景视频，切场景时才切换）。
  - 手机切后台时**暂停视频渲染**（省电），切回前台恢复。

### 10.2.3 音乐联动光效（锦上添花）
- 在背景层上方叠加一个**半透明渐变层**，颜色随专辑封面主色变化（提取封面HSL，动态渐变）。
- 可选：利用 `flutter_fft` 实时获取音频频谱，驱动粒子大小/速度（**默认关闭**，作为“炫酷模式”开关，避免耗电）。

## 10.3 Apple Music风格歌词系统（浮动层）

### 10.3.1 布局与动效
- **位置**：屏幕**居中偏上**（黄金分割点）。
- **样式**：每句歌词独立一行，**当前行字体放大（1.2倍）+ 加粗 + 白色高亮**，未到/已过行字体缩小（0.8倍）+ 半透明白色。
- **滚动动效**：歌词随播放进度**平滑上滑**（而非生硬跳转），类似Apple Music的逐行滚动。
- **背景衬底**：歌词区域背后有一个**竖向毛玻璃条**（`BackdropFilter`），宽度包裹最长歌词，高度自适应，不遮挡背景体素世界。

### 10.3.2 用户交互（解决同步问题）
- **手势**：在歌词区域**上下滑动**可手动滚动查看全部歌词。
- **偏移校准**：歌词右下角有一个**微小的“⏱️”图标**，点击后弹出滑块（-10s ~ +10s），调整后**自动存入该歌曲的数据库字段 `lyric_offset`**，下次播放直接套用。

### 10.3.3 无歌词/纯音乐处理
- 检测到纯音乐或无LRC文件 → 歌词区域自动**隐藏**，背景层**扩大为全屏**，底栏保持透明。
- 在设置中可强制开启“频谱可视化”替代歌词（跳动的柱状图）。

## 10.4 环境音效与3D空间音频（音效层）

### 10.4.1 场景白噪音叠加（氛围感核心）
**设计**：每个体素场景都自带一条**环境音轨**（如“雨夜”有雨声+雷声，“森林”有鸟鸣+溪流）。

**技术实现**：
- 使用 `media_kit` 或 `just_audio` 创建**第二个音频播放器实例（低优先级）**，专门播放循环的环境音效（`.mp3` / `.m4a`，码率64kbps即可，体积小）。
- **混音策略**：
  - 环境音音量默认为主音乐音量的 **30%**（用户可在设置中独立调节“环境音音量”滑块）。
  - 当主音乐暂停时，环境音**继续播放**（保持氛围不断）。
- **切换逻辑**：切换场景时，旧环境音**淡出（1秒渐变）**，新环境音**淡入（1秒渐变）**。

### 10.4.2 体素世界的3D空间音效（差异化杀手锏）
**目标**：让用户感觉声音来自体素世界的**特定方位**（比如鸟叫声从左上角传来，溪流声从右下角）。

**MVP实现方案（不走HRTF硬核路线）**：
利用 Flutter 的 `just_audio` 的 **`setChannelBalance()`** 和 **`setVolume()`** 组合，模拟简易3D定位：
- 假设体素世界以播放器为中心，声源被映射到 **左/右（-1 ~ 1）** 和 **远/近（0 ~ 1）** 二维坐标。
- **左右声道平移**：`setChannelBalance(leftVol, rightVol)`。
- **距离衰减**：`setVolume(1.0 - distance * 0.3)`。
- **高级幻想（可拓展）**：集成 `flutter_soloud` 的 `Audiosource` 3D接口，但鉴于包体积，**强烈建议MVP阶段只做“左右+音量”的简易3D**，在UI上标注“空间音效（Beta）”。

**触发时机**：用户启用“3D空间音效”开关后，将歌手的声像固定在虚拟场景的“舞台中央”，环境音分布在四周（背景音乐BGM走立体声）。

### 10.4.3 音效交互反馈（触感+听觉）
- **点击/滑动操作**：伴随极短促的“咔哒”UI音效（使用 `audioplayers` 播放本地短音频）。
- **切歌动画**：伴随一声轻微的“黑胶唱片静电”音效，强化仪式感。

### 10.11 体感沉浸式交互

#### 10.11.1 陀螺仪音量调节（旋转手机控制音量）

**传感器选型**：使用 **`sensors_plus`** 插件获取陀螺仪数据。

**核心逻辑**：监听设备绕 **Y轴（横向旋转）** 的角度变化，映射为音量值。

```dart
import 'package:sensors_plus/sensors_plus.dart';
import 'package:device_volume/device_volume.dart';

class GyroVolumeController {
  double _baselineAngle = 0.0;
  bool _isCalibrated = false;
  double _currentVolume = 0.5; // 0.0 ~ 1.0

  void startListening() {
    gyroscopeEvents.listen((GyroscopeEvent event) {
      // 绕Y轴的角速度（rad/s），积分得到相对角度
      // 简化方案：直接用绕Z轴的旋转（手机横握时更自然）
      final rotation = event.z; // 绕Z轴旋转角速度
      
      // 累积角度变化（需做阈值过滤，防止抖动）
      _accumulatedAngle += rotation * deltaTime;
      
      // 映射到音量：-45° ~ +45° 对应 0.0 ~ 1.0
      final mappedVolume = (_accumulatedAngle / 45.0).clamp(0.0, 1.0);
      
      if ((mappedVolume - _currentVolume).abs() > 0.01) {
        _currentVolume = mappedVolume;
        DeviceVolume.setVolume(mappedVolume * 100); // 0-100
      }
    });
  }

  void calibrate() {
    // 双击/长按触发校准，将当前角度设为基准
    _baselineAngle = _accumulatedAngle;
    _isCalibrated = true;
  }
}
```

**交互设计规范**：
| 手势 | 功能 | 反馈 |
|------|------|------|
| 手机**向左旋转**（绕Y轴） | 音量降低 | 音量条从右向左收缩 + 轻微震动 |
| 手机**向右旋转**（绕Y轴） | 音量升高 | 音量条从左向右扩张 + 轻微震动 |
| **双击**屏幕中央 | 校准基准角度 | 震动反馈 + Toast提示“已校准” |
| **长按**屏幕 | 临时锁定陀螺仪控制 | 震动反馈 + 锁定图标闪烁 |

**防误触机制**：
- 仅在**播放器全屏模式**下启用陀螺仪控制
- 角度变化 **< 2°** 时忽略（防抖动）
- 提供 **“陀螺仪控制”开关**，默认关闭（用户主动开启）

#### 10.12.2 多设备自适应延迟同步

**技术方案参考**：基于 **NTP时钟同步算法** + **预测补偿（Predictive Compensation）** 实现多设备毫秒级同步。

**架构设计**：

```
┌─────────────┐      NTP时间同步      ┌─────────────┐
│  主设备      │ ◄──────────────────► │  从设备1     │
│ (手机/平板)  │                       │ (音箱/电视)  │
└─────────────┘                       └─────────────┘
       │                                       │
       │  推送音频流 + 时间戳                    │ 播放
       ▼                                       ▼
┌─────────────┐                       ┌─────────────┐
│  音频流      │                       │  从设备2     │
│  HTTP Server │                       │ (另一音箱)   │
└─────────────┘                       └─────────────┘
```

**核心逻辑**：

```dart
class MultiDeviceSyncManager {
  // NTP时间偏移（设备与主时钟的偏差）
  double _timeOffset = 0.0;
  
  // 各设备已知延迟（ms）
  final Map<String, int> _deviceLatency = {};
  
  // 同步播放
  Future<void> syncPlay(String audioUrl, List<String> deviceIds) async {
    // 1. 获取主时钟时间戳
    final masterTimestamp = DateTime.now().millisecondsSinceEpoch;
    
    // 2. 计算各设备的目标播放时间（当前时间 + 预补偿延迟）
    for (final deviceId in deviceIds) {
      final latency = _deviceLatency[deviceId] ?? 200; // 默认200ms
      final targetTime = masterTimestamp + latency + _timeOffset;
      
      // 3. 发送指令：在 targetTime 时刻开始播放
      await _sendPlayCommand(deviceId, audioUrl, targetTime);
    }
  }
  
  // 延迟测量（ping-pong机制）
  Future<int> measureLatency(String deviceId) async {
    final start = DateTime.now().millisecondsSinceEpoch;
    await _sendPing(deviceId);
    final pong = await _waitPong(deviceId);
    final end = DateTime.now().millisecondsSinceEpoch;
    return (end - start) ~/ 2; // 往返延迟 / 2
  }
}
```

**同步精度目标**：
| 场景 | 目标延迟差 | 实现难度 |
|------|-----------|----------|
| 同设备多输出（蓝牙+扬声器） | < 50ms | 低（系统级处理） |
| 同WiFi多音箱 | < 100ms | 中（NTP同步） |
| 跨网络多设备 | < 200ms | 高（需专用中继服务器） |

## 3. 核心模块详解

### 3.1 文件系统抽象层

**设计目标**：统一本地路径、SMB网络挂载、WebDAV（阿里云盘）的访问方式，扫描引擎只认抽象接口。

```dart
abstract class VirtualFileSystem {
  Future<bool> exists(String path);
  Future<Uint8List> readBytes(String path);
  Future<List<FileStat>> listDirectory(String path);
  Future<int> fileSize(String path);
  Future<DateTime> lastModified(String path);
  Stream<List<int>> openRead(String path, {int? start, int? end});
}
```

| 实现类 | 适用场景 | 关键实现（v3.0 实际） |
|--------|----------|----------|
| LocalFileSystem | 手机本地存储 | dart:io |
| WebDavFileSystem | 阿里云盘/NAS（WebDAV） | **纯 Dart `WebDavClient`（webdav_client.dart）**：PROPFIND + Depth:1 + Basic 头 + 正则解析 multistatus（容忍任意命名空间/XML 数字实体），零 JVM/原生依赖 |
| SmbFileSystem | NAS SMB共享 | **后补**（jcifs-ng 未引入，纯 Dart 方案待调研） |

> v3.0 偏离说明：v2.0 原写 WebDAV 走 dio + http_parser、SMB 用 jcifs-ng。实际 T12 落地为纯 Dart + http 包的 `WebDavClient`，可注入 `MockClient` 单测；SMB 因 JVM 依赖隔离成本后补。

### 3.2 音频元数据解析与刮削

**元数据解析**：使用media_kit的peek()方法提取title/artist/album/year/coverArt/duration；本地库另用 on_audio_query 读实时元数据。

**刮削策略（T12 已落地）**：
- 线上数据源：**MusicBrainz（`scraper.dart`，recording 查询）+ coverart 缩略图 URL**，自定义 UA + 1.3s 节流（遵守 service terms），429 优雅降级
- 本地优先：同目录cover.jpg/folder.jpg，内嵌ID3封面
- 分散补充：Discogs 封面扩充（后补，未排期）

**CUE分轨处理（T12 已落地）**：**纯 Dart `CueParser`（cue_parser.dart）** 解析 `mm:ss:ff`（75帧/秒）→ Duration；`INDEX 01` 为曲目起点、`INDEX 00` 为前奏；`withEnds()` 按下一轨起点推导轨尾；Track 模型新增 `cueStartMs/cueEndMs`，播放加载成功后自动 seek 到起点。投屏时可按字节 Range 切片推送。

### 3.3 本地HTTP流媒体服务（投屏核心）

**设计原则**：零拷贝、分块推流、支持Range请求（进度拖动）。

**Range解析器**（支持bytes=0-100 / bytes=512- / bytes=-1024三种格式，v3.0 实际为 `CastStreamServer`）：

```dart
void _handleTrack(HttpRequest req, ...) {
  // 本地文件：File.openRead(start, end + 1) → 206 + Content-Range: bytes a-b/total
  // 远程代理：透传 Range 头到上游
  // 后缀范围：bytes=-N → 末尾 N 字节
}
```

**v3.0 实际实现（T11 落地）**：`CastStreamServer`（cast_stream_server.dart）——纯 dart:io `HttpServer.bind(anyIPv4, 8741)`，端口被占 +1 重试（≤10 次）；路由：
- `/` —— HTML 播放页（JS 解析 `?uri=`）
- `/track?uri=` —— 本地 Range 切片 206 / 远程 http 代理透传
- `/info` —— JSON 元信息

`server.idleTimeout = Duration(hours: 2)` 长驻；**功能开关 + 端口/IP 展示 + 当前曲目直链**由 `cast_providers.dart` 驱动 UI（探索页「投屏」卡片）。3 个冒烟测试验证 206 + Content-Range 语义。

**DLNA与AirPlay策略（后补）**：
- DLNA：APP作为DMC控制点，推送HTTP流地址
- AirPlay 2：调起系统原生路由器
- 投屏音质：DSN 方式直通（详见《投屏与网络源实施方案》）

### 3.4 播放状态协调器

**核心问题**：防止本地切歌导致投屏中断，防止投屏时文件被占用的文件锁冲突。v3.0 实际由 `AudioService`（audio_service.dart）统一仲裁：多后端路由（media_kit / just_audio / audioplayers，按 `requiresMediaKit` 标志与占用情况选择）+ 播放占位/真实 URL 解析（`buildStreamResolver`）+ WebDAV 认证头注入。

```dart
class PlaybackCoordinator {
  enum ActiveOutput { none, local, dlna }
  final ValueNotifier<ActiveOutput> activeOutput = ValueNotifier(ActiveOutput.none);
  final Map<String, int> _fileReadCount = {};
  
  bool requestPlayback(String filePath, ActiveOutput requester);  // 冲突时强制剥夺旧输出
  void acquireFileLock(String path);   // 投屏读文件时加锁
  void releaseFileLock(String path);   // 响应结束时释放
  bool isFileLocked(String path);      // media_kit切歌前检查
}
```

### 3.5 扫描引擎

**双速扫描模式**（v3.0 已落地）：

| 模式 | 策略 | 性能 |
|------|------|------|
| 极速模式 | 比对文件夹lastModified + fileSize | 1万首歌 < 200ms |
| 深度模式 | 强制重新解析元数据 + CUE | 按需触发 |

- 静态截图：MagicaVoxel预渲染4K PNG（低性能设备/省电模式）
- 循环视频：HEVC编码无缝循环MP4（默认推荐）
- 粒子光效：Flutter CustomPaint + 频谱联动

**视频背景播放策略**：

- 切歌时不重新加载视频（预加载3个场景）
- APP切后台暂停视频渲染

### 4.3 Apple Music风格歌词系统

**布局**：居中偏上，当前行字体1.2倍+加粗+白色高亮，已过/未到行0.8倍+半透明。

**交互**：
- 上下滑动手动滚动查看全部歌词
- 歌词偏移校准滑块（-10s ~ +10s），存入数据库lyric_offset字段
- 无歌词/纯音乐自动隐藏歌词区域

### 4.4 环境音效与空间音效

**环境白噪音**：使用独立的`flutter_soloud`实例播放循环环境音轨（雨声、鸟鸣、溪流），音量默认为主音乐的30%，切换场景时1秒交叉淡入淡出。

**简易3D空间音效**（MVP）：
- 使用flutter_soloud的setVolume + 左右声道平衡模拟3D定位
- 声源映射到左/右（-1~1）和远/近（0~1）二维坐标
- 标注“空间音效（Beta）”，不承诺Hi-Fi效果

### 4.5 外部视频源接入（v3.0 实际）

- **B站（已落地，T7）**：免登录搜索 + 登录内置网页抓 Cookie；视频作场景背景（`scripts/bilibili` 源），曲名匹配自动播放 + 设置开关

**陀螺仪音量调节**：
- 使用`sensors_plus`监听绕Y轴旋转角度
- 映射：-45°~+45°对应音量0.0~1.0
- 双击屏幕校准基准角度
- 仅在全屏播放器模式下启用

**环境光自适应**：使用`dynamic_theming`插件，lux阈值50以下切换暗色模式，800ms平滑过渡。

**横屏适配**：

- 双指捏合缩放视频背景
- 左右滑动切换歌曲

### 4.7 多设备同步播放（v3.0：已落地）

**现状（偏离 v2.0 规划说明）**：基于 HarmonyOS 软总线的思路已实际落地为 **中继 + 房间模型**：

- **中继服务**：`tools/relay_server/relay_server.dart`（Dart 编译 exe，监听 8092，公网可达），提供场景/歌单/公告内容 + 联机中继；开机自启计划任务 `XingliRelayAutostart`

## 5. 外部服务集成

### 5.1 登录与Cookie管理

**v3.0 实际演进（偏离 v2.0 说明）**：v2.0 规划 WebView + cookie_jar + dio_cookie_manager 方案，实际按平台各自收敛：

- **网易云（已去扫码）**：cookie 直连 + 加密存储，登录态失效自动重登引导；Windows 登录调起系统浏览器
- **B站（免登录默认）**：未登录走免登录搜索（T7 落地，含结果音质提示）；登录用**内置网页页面自动抓取** Cookie，无需跳外部浏览器
- Cookie 加密存储沿用 secure storage 语义（P-3 SecureBox 密钥落盘已完成）

> T3 原则约束：登录只为「官方接口直连」服务，严禁把凭据转交任何第三方代理。

### 5.2 网易云服务集成（T3 修订核心）

**v3.0 实际（偏离 v2.0 说明）**：v2.0 原引用 Binaryify/NeteaseCloudMusicApi 开源代理项目。**T3 拍板禁止**——改为**自研 weapi 加密直连**：

- `netease_crypto.dart`：weapi 协议加密（AES-CBC + RSA 两步），复现官方 web 端取流
- `netease_api.dart`：HTTP 客户端 + 模型（login / 搜索 / 每日推荐 / 漫游 / 歌单 / 播放 URL 解析），纯 Dart + http
- `netease_source.dart`：MusicSource 实现，占位 uri（`netease://`）+ `resolveStreamUrl` 出真实播放地址
- **歌单分页（T8）**：PagedMusicSource，网易云歌单整单拉取
- 入口：探索页「网易云歌单」「每日推荐」「漫游」卡片

**降级方案**：
- Cookie 失效（401）自动刷新/提示重新登录
- 本地缓存命中优先，弱网不阻塞

## 6. 性能与功耗优化

### 6.1 音频播放优化

| 优化项 | 策略 | 效果 |
|--------|------|------|
| 预加载 | AVPlayer预加载3-5秒 | 应对网络波动 |
| 解码优先级 | 优先硬件解码 | 降低CPU占用 |
| 后台资源 | 后台暂停可视化渲染 | 保留核心播放线程 |
| 电量优化 | 进度更新频率100ms→500ms | 减少CPU唤醒 |

### 6.2 内存与存储优化

- 投屏推流：64KB分块推送，禁止readAsBytesSync
- 封面加载：缓存200x200缩略图，释放原图
- 大列表滚动：ListView.builder + AutomaticKeepAlive
- 缓存清理：超100MB自动清理

### 6.3 功耗红线

| 场景 | 要求 | 降级策略 |
|------|------|----------|
| 低电量(<20%) | 自动关闭视频背景 | 切换为静态截图 |
| 低性能设备(RAM<4GB) | 默认静态截图 | 用户可手动开启“性能模式” |
| 切后台超5分钟 | 释放视频解码器 | 切回前台重新初始化 |
| 蜂窝网络 | 不预加载新场景视频 | 提示“非WiFi环境，视频延迟加载” |

## 附录B：常见踩坑记录

| 问题 | 原因 | 解决 |
|------|------|------|
| 投屏几秒后停止 | Content-Length不匹配或分块提前关闭 | 检查Range响应正确设置Content-Length |
| 歌词与音乐不同步 | 各版本音频文件时长差异 | 提供手动偏移滑块，存入数据库 |
| Android 12后台解码失败 | 系统限制后台CPU | 使用前台服务通知+声明FOREGROUND_SERVICE_MEDIA_PLAYBACK |
| 陀螺仪控制过于敏感 | 角度抖动未过滤 | 设置死区阈值<2°忽略 |
| 视频背景切场景卡顿 | 未预加载 | APP启动时预加载3个场景首帧 |
| WebView与Dio Cookie不同步 | 两份Cookie Jar未同步 | 使用flutter_cookie_bridge或手动同步 |
