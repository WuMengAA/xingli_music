## 🏗️ 星璃音乐 · 构建手册

### 0️⃣ 环境（本机已配好，别乱动）

| 项 | 位置 |
|---|---|
| Flutter | `D:\flutter\bin\flutter.bat`（**不在 PATH**，要用全路径） |
| Android SDK | `D:\Android\Sdk`（=`ANDROID_HOME`） |
| Gradle 缓存 | `D:\.gradle`（=`GRADLE_USER_HOME`，约 8.5G） |
| 项目 | `D:\Stellara\Music\xingli_music` |
| 产物目录 | `D:\Stellara\Music\xingli_music\release\` |

> ⚠️ **构建命令必须显式带两个环境变量**，否则 Gradle 会悄悄回 C 盘重建缓存（冷启动 10+ 分钟）：
> ```bash
> export GRADLE_USER_HOME=D:/.gradle
> export ANDROID_HOME=D:/Android/Sdk
> ```
> 注意用**正斜杠**——Git-Bash 双引号会吞反斜杠，写成 `D:\.gradle` 会变 `D:.gradle`（非法）然后静默回 C 盘。

### 1️⃣ 构建前检查（30 秒，缺一步就卡死）

```bash
ls build/media_kit_libs_android_video/v1.1.7/   # 必须看到 4 个 jar
```
- media_kit 原生库**本机无法从 GitHub 下载**（网络墙），jar 预先放在 `D:\Stellara\Music\assets`，已复制到工程 `build/` 下。
- **绝不执行 `flutter clean`**——会把 jar 清掉，下次构建卡死在下载墙。

---

### 2️⃣ 版本号三处同步（构建前必做，缺一不可）

| 文件 | 改什么 |
|---|---|
| `lib/core/app_version.dart` | `buildCount`（当天该渠道构建次数，cl01 起）、`day`（真实日期）、`channel`（beta/alpha）、`changelog` 顶部加条目 |
| `android/app/build.gradle` | `versionCode`（**必须单调递增**，92→93，不能清零否则装不上）+ `versionName`（如 `0.26.08.19_alpha_cl01`，月补零） |
| `pubspec.yaml` | `version: 0.26.8+93` |

> cl 编号规则：**当天该渠道第几次构建**（beta/alpha 各自从 01 数），跨天清零；`versionCode` 不清零。

---

### 3️⃣ Android APK（约 1.5~2.5 分钟，热缓存）

```bash
cd "D:/Stellara/Music/xingli_music"
export GRADLE_USER_HOME=D:/.gradle
export ANDROID_HOME=D:/Android/Sdk
"D:/flutter/bin/flutter.bat" build apk --release --no-tree-shake-icons -P disable-abi-filtering=true
```
- 产物在 `build/app/outputs/flutter-apk/`：
  - `app-arm64-v8a-release.apk`（44MB，新手机）
  - `app-armeabi-v7a-release.apk`（41MB，老机器）
- **结尾若报 "failed to produce an .apk file" 是误报**（splits.abi 拆分包的已知现象），包实际正常，直接去 flutter-apk 目录取。
- `-P disable-abi-filtering=true` 必须带（Flutter 3.44.8 与项目 ABI 拆分配置冲突，官方 flag 规避）。

---

### 4️⃣ Windows EXE（约 1.5 分钟）

```bash
"D:/flutter/bin/flutter.bat" build windows --release --no-tree-shake-icons
```
- 产物在 `build/windows/x64/runner/Release/`：
  - `xingli_music.exe` + `data/` + 所有插件 DLL + **`sqlite3.dll`**
- ⚠️ **必须整个 Release 目录一起分发**，不能只复制 exe（否则运行崩）。

---

### 5️⃣ 收集产物到 release/（复制不许移动）

```bash
REL="D:/Stellara/Music/xingli_music/release"
cp build/app/outputs/flutter-apk/app-arm64-v8a-release.apk "$REL/星璃音乐_0.26.8.19_alpha_cl01.arm64.apk"
cp build/app/outputs/flutter-apk/app-armeabi-v7a-release.apk "$REL/星璃音乐_0.26.8.19_alpha_cl01.arm32.apk"
cd "$REL" && sha256sum 星璃音乐_*.apk > 星璃音乐_0.26.8.19_alpha_cl01.arm64.apk.sha256
```
命名规则：`星璃音乐_<版本串>.<架构>.apk`，不带代号（与历史一致）。

### 6️⃣ Windows 打包（两个产物）

**便携 zip**（7z 打压缩包）：
```bash
# 先复制 Release 到 ASCII 临时目录（中文路径 7z 会踩 glob/编码坑）
cp -r build/windows/x64/runner/Release D:/temp/xingli_win_clXX
cd D:/temp && "C:/Program Files/7-Zip/7z.exe" a -tzip -mx=9 D:/temp/x.zip xingli_win_clXX
# 再 mv 成中文名（注意：7z 写盘需 dangerouslyDisableSandbox）
```

**安装包**（Inno Setup 向导）：
1. 先改 `tools/inno_xingli.iss` 里的版本号（`MyAppVersion` + `OutputBaseFilename`）
2. 编译：
```bash
"C:/Users/Administrator/AppData/Local/Programs/Inno Setup 7/ISCC.exe" tools/inno_xingli.iss
```
> ⚠️ `ISCC.exe`/`7z.exe` 写盘会被沙箱**静默拦截**（提示成功但文件没落地），必须用 `dangerouslyDisableSandbox: true` 跑。

## 📌 常见坑速查

| 症状 | 原因 | 修法 |
|---|---|---|
| 构建卡在下载 | media_kit jar 没了 | 检查 `build/media_kit_libs_android_video/v1.1.7/`，从 `assets` 复制 |
| 构建巨慢 | Gradle 回 C 盘 | `GRADLE_USER_HOME=D:/.gradle` 正斜杠 |
| 装不上 | versionCode 回退 | 单调递增 |
| exe 运行崩 | 少了 sqlite3.dll / data/ | 整个 Release 目录分发 |
| "failed to produce apk" | splits.abi 误报 | 忽略，去 flutter-apk 取 |
| zip/setup 缺失 | 沙箱拦外部 exe 写盘 | `dangerouslyDisableSandbox: true` |
