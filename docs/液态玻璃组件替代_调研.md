# 液态玻璃组件替代 · 调研决策

> 日期：2026-08-31（拍板日随案）
> 背景：用户拍板「全方位应用转型」关注**液态玻璃界面组件的替代方向**（见 `docs/方案_全方位转型.md` §8）。
> 现状：`lib/widgets/liquid_glass.dart` 已全量迁移到 `liquid_glass_widgets`（[AdaptiveGlass]），`kNativeMinimal=true` 下 30 余处默认直通、仅 Dock/音乐控制栏 forceGlass 白名单走真玻璃。

## 3. 决策建议

**维持 `liquid_glass_widgets` 为唯一玻璃容器依赖，不引入替代。** 理由：

1. **维护活跃**：1.2.1 于调研当日发布，无弃坑风险。
2. **已深度沉淀**：`lib/widgets/liquid_glass.dart` 的公共 API 抽象（LiquidGlass/GlassStyle/forceGlass）20+ 调用点零改动，R32 已做 RepaintBoundary 图层隔离治理——替换的迁移成本与回归面远超收益。
3. **渲染器无关回落**：Impeller/Skia/web 三端自动选择，Windows 桌面（Skia）走轻量路径，正是本应用主力平台。
4. **候选库无一完胜**：或停滞（liquid_glass）、或定位错位（镜头/水滴/导航栏）、或 dev 版不稳定（renderer）。

**可行的"替代感"动作（不换依赖）**：
- **升级到最新 1.2.1**：吃满维护修复（需回归验证玻璃焦点 Dock/控制栏视觉）。
- **收窄 forceGlass 白名单**：已只留 Dock + 音乐控制栏两处"玻璃焦点"——这正是"以极简基底 + 玻璃点缀"替代"全站玻璃"的方向，已达成。
- **平台差异化**：Windows 桌面可评估仅这两处用玻璃、其余 native 直通；Android/Web 同理。

---

## 4. 决议与后续

- **决议**：继续使用 `liquid_glass_widgets`；暂缓引入任何替代包。
- **后续项**（非本轮）：①升级 1.2.1 后跑视觉回归（Dock/控制栏玻璃焦点、主题切换）；②若未来发布者停更，再重新评估 `liquid_glass_easy`（活跃）或自研 shader。
- **关联**：`lib/widgets/liquid_glass.dart`（现状文档）、`docs/方案_全方位转型.md` §8。
