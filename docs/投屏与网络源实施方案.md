## 1. 投屏（T11 · 最小版）

### 原理
纯 `dart:io HttpServer` 监听局域网（默认端口 8741，冲突自动 +1），
同网段设备用浏览器 / VLC / 系统播放器打开地址即可播放**正在播放的曲目**：

| 路由 | 说明 |
|---|---|
| `GET /` | 迷你 HTML 播放页（自动解析 `?uri=`，`<audio>` 播放） |
| `GET /track?uri=<u>` | 音频流。本地文件 `Range: bytes=a-b` 切片直读（206 + Content-Range）；http(s) 远程流用 `http.Client` 代理转发并透传 Range 语义 |
| `GET /info?uri=<u>` | JSON 元信息（标题/艺术家/封面） |

### 关键文件
- `lib/services/cast/cast_stream_server.dart` —— 服务本体（零新依赖）
- `lib/providers/cast/cast_providers.dart` —— 启停 + 端口 + 本机 IP 状态
- `lib/pages/explore/experiments/cast_page.dart` —— 投屏页（开关/IP/链接复制）
- `test/cast_stream_server_test.dart` —— HTTP 冒烟测试（Range 切片 206 断言）

### 后补
- **DLNA**：电视盒已能直接播 `/track` 直链；后续可加 `didl-lite` SSDP 描述变成真正的 DLNA 服务器。
- **AirPlay / Chromecast 系统投屏**：依赖平台私有协议（RAOP / Cast V3），需求量大或确定具体
  目标设备时再评估（Android 侧 Cast 需 Google Play Services，体积 + 审查成本高）。

## 2. 网络音乐库（T12 · WebDAV）

### 原理
自研最小 WebDAV 客户端（`http` 包 + PROPFIND，正则解析 multistatus，
容忍任意命名空间前缀）：

- **配置**：地址/用户名/密码存入 `SharedPreferences`（`webdav_configs_v1`）
- **浏览**：`WebDavClient.list(path)` 返回目录/文件条目，页面面包屑逐级导航
- **播放**：点音频文件 → 构造 `MusicSource` 占位 uri
  `webdav://<base64url(绝对路径)>`，`sourceId='webdav:<configId>'`；
  `WebDavSource.resolveStreamUrl` 还原真实 http(s) 地址，
  `playbackHeaders` 携带 `Authorization: Basic` 头 → `AudioService`
  加载时附带认证头直接流播，**不落盘**
- 不支持服务器：401/403 → 中文提示；PROPFIND 超时 20s

### 关键文件
- `lib/services/network/webdav_client.dart` —— PROPFIND 客户端 + 条目模型
- `lib/services/network/webdav_source.dart` —— MusicSource 实现（占位→真实流 + Basic 头）
- `lib/providers/network/webdav_providers.dart` —— 配置持久化 + 源集合 + 占位 uri 工具
- `lib/pages/explore/experiments/net_library_page.dart` —— 配置管理 + 目录浏览 + 播放

### SMB（后补）
SMB2 协议协商（SPNEGO/NTLM）复杂度高、纯 Dart 成熟实现少；
WebDAV 已覆盖同场景（NAS/群晖/共享目录），SMB 等到有明确用户需求再评估
`smb_connect` 类纯 Dart 包或原生插件。文件系统抽象层（`RemoteFileSystem`）
可作为后续接入点——当前 `WebDavSource` 已把「远程源」收敛到
`MusicSource` 单一接口，新增 SMB 只需再实现一个 Source。

## 3. CUE 分轨（T12）

### 原理
纯 Dart 解析器 `parseCue(String)`：

- 支持 `FILE / TRACK / TITLE / PERFORMER / INDEX 00/01 / REM`
- 时间 `mm:ss:ff`（75 帧/秒）→ `Duration`；`INDEX 01` 为曲目起点，`INDEX 00` 为前奏
- 轨级元数据缺省回退专辑级；`withEnds()` 按「下一轨起点」推导每轨结束点

### 播放接线
`Track` 新增 `cueStartMs` / `cueEndMs`（毫秒，顶层字段，随 toJson/fromJson/copyWith
同步）。`AudioService._prepareMusic` 加载成功后若 `cueStartMs > 0` 自动 `seek`，
实现**整轨文件逐轨播放**（无需切割文件）。

`start_byte / end_byte`（字节偏移）：CUE 表本身不含码率信息，字节偏移无法精确推导。
当前以**毫秒级 seek** 实现分轨（无损场景下 seek 等价）；字节级偏移（按
`码率 × 时间 / 8000` 估算，写入 extras 供未来 **DSN 无损直通裁剪** 参考）作为预留，
见第 5 节。

### 关键文件
- `lib/services/cue/cue_parser.dart` + `test/cue_parser_test.dart`（5 用例）
- `lib/models/track.dart`（cueStartMs/cueEndMs）
- `lib/services/audio/audio_service.dart`（cueSeek）
- `lib/pages/explore/experiments/cue_sheet_page.dart`

## 4. 刮削器（T12 · MusicBrainz）

- `MusicBrainzScraper.search(title, artist)` → `ws/2/recording?fmt=json&query=...`
- 命中项含标题/艺术家/专辑（首 release）/时长/封面（coverartarchive 缩略图）

- 关键文件：`lib/services/musicbrainz/scraper.dart` + 3 测试用例、
  `lib/pages/explore/experiments/scraper_page.dart`

## 5. DSN 直通说明

**DSN（Digital Stream Native）= 音频直通**：bit-perfect 把原始采样数据直送
渲染器 / 外接 DAC，不经重采样、不经软混音、不加 EQ 处理链，保留 Hi-Res 原始流。

当前实现与预留：

| 层面 | 现状 |
|---|---|
| 播放加载 | 本地文件 `openPath` 不经转换直送解码器；CDN 流 `openUri`/`openUrl` 带原请求头 |
| 引擎 | `media_kit`（libmpv）支持 Hi-Res/FLAC 原样；`just_audio` 默认链 |
| EQ 链 | 直通模式下可关闭软件 EQ/音效，保证原始比特流不被处理 |
| 外接 DAC | 依赖系统输出设备选择；平台原生层直通（如 USB Audio Class）后续评估 |
| CUE 分轨 | 毫秒 seek 已示意性等值；字节级 `start_byte/end_byte` 偏移预留（见第 3 节），
  未来做无损流裁剪（HTTP Range 切片投屏已具备字节级语义） |

> 说明：投屏链路（`/track` Range 切片）本身就是字节级直通——文件按 `start-end`
> 原样切出传输，不做转码，天然符合 DSN 语义。
