# 博客子模块 · 渲染/托管选型对比（决策素材稿）

> 定位：为「全方位转型」3 问中的「博客形态/导入导出」提供决策素材。
> 对齐 `方案_全方位转型.md` §4：博客 = **应用内自有内容输出**（单作者、Markdown、本地渲染、无评论/无公开广场、不上传——符合白皮书铁律 1/2）。
> 选型分两层：**A 应用内渲染引擎**（P1 主体）+ **B 可选外部网站镜像**（后续可选，非 P1 范围）。

## A. 应用内渲染引擎（P1 主体）

| 方案 | 技术栈 | 优点 | 代价 |
|---|---|---|---|
| **`flutter_markdown`** | Dart（Flutter 官方生态，活跃维护） | 开箱即用：块/行级样式 + 图片/链接/表格 + 主题定制点；社区案例多 | 新增 1 个依赖；深定制（代码高亮等）需扩展 builder |
| **`markdown` 包 + 自渲染** | Dart（纯解析，无 UI） | 解析与 UI 解耦，可配星璃液态玻璃风格 | 渲染层全自研（表格/图片/脚注都要自己写），工作量×3 |
| 自研解析器 | Dart | 零依赖 | 不推荐：Markdown 规范面太宽，维护地狱 |

**推荐 A1：`flutter_markdown`**（v1：列表/阅读页 + `assets/example_blog/` 2 篇示例；自定义主题色接入星璃五色板）。
已知先例：ClassIsland 插件市场 README 即用 Markdown 渲染；`flutter_markdown` 是 Flutter 官方引用的社区标准实现。

> 备注：星璃仓库当前**无 Markdown 依赖**（pubspec 核实），引入 `flutter_markdown` 不冲突。

## B. 外部网站镜像（可选，非 P1）

若后续想「把博客同步成公开网页」（自建发布，非社交），静态站候选：**Astro**（文档+博客单站，GitHub Pages 直出，clOTA 的 gh-pages 基建可直接复用 `blog/` 目录）＞ Docusaurus（文档版本化强，博客弱）＞ Hugo（单二进制最省心，与 Dart 无交集）。不建议自建 Dart 生成器（生态空白）。

- 与铁律对齐：镜像仅单向发布自有内容，不接评论/推荐 API。
- 触发条件：用户把「对外网页博客」纳入路线（3 问之外的新决策）；P1 不依赖它。

## 决策点（供拍板）

1. **A 引擎选 A1（flutter_markdown）**：默认推荐，除非要求完全自研 UI。
2. **导入导出**：方案 §7 问 3——v1 仅本地目录扫描（`assets/example_blog/` 引导语义：用户把 md 放进应用文档目录），不做 zip 导入；如需导出→「打包 zip」可后补（archive 依赖已在 OTA 使用，成本低）。
3. **B 网站镜像**：本次不启动，仅记录意向。
