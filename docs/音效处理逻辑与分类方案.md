# 音效处理逻辑与分类处理解决方案

> 范围：星璃音乐 App 内所有「声音」的处理链路、分类、使用位置、全局性、可自定义性，
> 以及**全局命名统一规范**。本文对应需求第 6 点（输出完整音效处理逻辑与分类方案）。
> 所有结论均对照当前代码（`lib/services/audio/audio_service.dart` 等）写实，非空想。

---

## 0. 一句话架构

App 内共有 **5 个独立播放器实例**（多音轨）+ **1 个反馈提示播放器 `_cue`**（分类音量拖动时的瞬时反馈音），
统一经 `AudioService` 收口；所有通道输出乘以「主音量 Master」；各通道另带独立音量 / 静音。
淡入淡出、交叉淡化、世界音效刷新全部走 **异步任务（协作式多线程）**，不阻塞 UI。

> 声音现分 **6 个分类**（`AudioCategory` 枚举：音乐 / 背景声 / 白噪音 / 音效 / 世界空间音效 / 提示音），
> 每个分类在设置页有独立音量条，拖动时会播放该分类的代表性反馈音（见 §2.6）。

| 实例 | 类型 | 承载分类 | 关键点 |
|------|------|----------|--------|
| `_music` | `MusicBackend`（just_audio / media_kit） | 音乐 | 主曲，支持 EQ |
| `_scA` / `_scB` | `audioplayers.AudioPlayer` | 背景声/音景 | 双实例交叉淡化 |
| `_wn` | `audioplayers.AudioPlayer` | 白噪音 | 独立循环通道（支持「跟随场景 / 全局」二选一） |
| `_sfx` | `audioplayers.AudioPlayer` | 一次性音效 | 游戏事件触发 |
| `world_audio_engine` | 4 轨预算 | 世界空间音效 | 随相机位姿变化的定位音 |
| `_cue` | `audioplayers.AudioPlayer` | 提示音（反馈） | 分类音量拖动时的瞬时确认音，220ms 节流 |

## 2. 各类详解（处理链路）

### 2.1 音乐（Music）
- **触发**：`AudioService.playMusic(Track)`；续播/暂停走状态机 `PlaybackState`。
- **链路**：解析占位符（`netease://` → `buildStreamResolver`）→ `openUrl/openPath/openUri`
  → 直接落到目标音量再 `play()`（已修复「须拖音量才有声」）→ 可选淡入。
- **全局性**：是。受 Master 音量乘算；Android 真 EQ 仅作用于此通道。
- **自定义维度**：音乐声量、静音、`musicEngine`（just_audio / media_kit）、均衡模式（高保真/普通）。
- **修复点（本轮）**：切歌不再从 0 淡入，改为先设目标音量再播，规避部分 Android 解码器锁死静音。

### 2.2 背景声 / 音景（Soundscape）
- **触发**：`AudioService.switchSoundscape(Scene)`；换场景时双播放器交叉淡化。
- **链路**：优先用户素材 `AssetSource` → 否则 Minecraft 环境音 / 程序合成 WAV →
  `next.resume()` 与 `prev.stop()` 并行淡变（3s）。
- **全局性**：跟随当前场景，不是「独立于界面常驻」。离开场景应停（已用 `mixWithOthers` 不抢焦点，不打断音乐）。
- **自定义维度**：背景声音量、静音。

### 2.3 白噪音（WhiteNoise）
- **触发**：`AudioService.setWhiteNoise(bool)` / `setWhiteNoiseVolume(double)`。
- **链路**：懒加载合成 WAV → `ReleaseMode.loop` 循环 → 独立音量叠加于音乐/音景之上。
- **全局性（本轮重构）**：白噪音来源支持「跟随场景 / 全局播放」二选一，由
  `whiteNoiseFollowsSceneProvider`（`true`=跟随场景）控制：
  - **跟随场景**：开关与音量取**当前激活场景**的值（`Scene.whiteNoise` / `Scene.whiteNoiseVolume`），
    切换场景即自动换用该场景的底噪配置。
  - **全局播放**：开关与音量取全局 `whiteNoiseEnabledProvider` / `whiteNoiseVolumeProvider`，与场景无关。
  - 对外统一经 `effectiveWhiteNoiseProvider`（`({bool on, double volume})` 记录）解析，
    所有监听方只读这一个 provider，避免「跟随场景」被全局监听覆盖。
  - 场景级配置写入走 `saveSceneWhiteNoise(ref, on:, volume:)`，内置场景也按 `id` 存为覆盖副本
    （经 `customScenesProvider`），不会打乱场景顺序（顺序由固定 seed 决定）。
- **自定义维度**：开关、音量（场景级或全局级二选一）。
- **持久化**：`whiteNoiseFollowsSceneProvider`、`whiteNoiseEnabledProvider`、`whiteNoiseVolumeProvider`
  均经 `SettingsRepository` 落盘；恢复设置时统一读 `effectiveWhiteNoiseProvider` 后下发给 `_wn`。

### 2.4 音效 / SFX
- **触发**：`AudioService.playSfx(path)`；由 Minecraft 主题音效调度器在游戏事件调用。
- **链路**：`setVolume(单次 × sfxVolume × master)` → `setAudioSource` → `play()`。
- **全局性**：否，仅体素世界交互时出现。
- **自定义维度**：音效音量（`sfxVolume`）。

### 2.5 世界空间音效（WorldSpatial）
- **触发**：进入 3D 视图时 `world_audio_engine` 起播；每帧按相机位姿刷新增益/声像/隔音。
- **链路**：4 音轨预算（水/风/叶/鸟）→ 按地标锚点（center/water/tree/mountain/fire）定位 →
  `_stepCamera` 风格指数逼近，随地形/机位变化。
- **全局性**：否，仅 3D 世界内。
- **自定义维度**：各源增益（经 `VoxelSoundEditorPage`）+ **全局增益 `worldSfxVolume`**
  （本轮新增 `AudioService.worldSfxVolume` / `worldSfxVolumeProvider`，范围 0–1，默认 0.6）。
  - **当前接线方式**：`worldSfxVolume` 在 `AudioService` 内仅作内存记录，**尚未经 `AudioService` 直接下发引擎**；
    实际音量在 `VoxelWorldView3D` 中由 `WorldAudioEngine.setGlobalVolume(worldSfxVolume × master)` 应用，
    并监听 `worldSfxVolumeProvider` / `masterVolumeProvider` 实时刷新。
  - **待办**：把 `worldSfxVolume` 经 `AudioService.setWorldSfxVolume` 统一收口下发到引擎，消除双路接线。

### 2.6 提示音（UiCue）
- **触发**：拖动任一分类音量条 / 部分界面操作 → `AudioService.playCategoryCue(AudioCategory)`。
- **链路**：`SoundscapeGenerator.ensureCategoryCue(tag)` 程序合成 6 类代表性短音（音乐=音阶 / 背景声=风声 /
  白噪音=沙沙 / 音效=咔哒 / 世界空间=脚步 / 提示音=叮），缓存到 `__cue_<tag>` 文件 → `_cue` 播放器播放。
- **节流**：同一分类 220ms 内只播一次，避免拖动滑块时音效轰炸。
- **音量**：取「分类记忆音量 × 主音量 Master」，随拖动实时变化，给用户即时听感反馈。
- **全局性**：是，`_cue` 为独立通道，不参与场景/游戏事件。
- **自定义维度**：提示音整体音量 `uiCueVolume`（`AudioService.uiCueVolume` / `uiCueVolumeProvider`，默认 0.5）。

## 3. 处理链路（代码级总图）

```
用户操作 / 场景切换 / 游戏事件
        │
        ▼
   AudioService（唯一收口）
   ├─ playMusic        → _music      （音乐，主通道，可 EQ）
   ├─ switchSoundscape → _scA / _scB （音景，交叉淡化）
   ├─ setWhiteNoise    → _wn         （白噪，独立循环）
   ├─ playSfx          → _sfx        （一次性音效）
   └─ (world) world_audio_engine（4 轨空间音效，仅 3D 世界）
        │
        ▼
   各通道音量 = 记忆音量 × 主音量(Master) × 均衡曲线
        │
        ▼
   淡入/淡出/交叉淡化：异步任务（不阻塞 UI）= 协作式多线程
        │
        ▼
   音频后端：just_audio（Android 真 EQ）/ media_kit（libmpv，多线程解码）
```

**主音量乘算（本轮修复）**：`setMasterVolume` 旧代码误将 `_masterVol` 乘了两次，
已改为单次乘算；否则拖动主音量会出现「音量被压低」的诡异手感。

## 4. 多线程 / 多音轨设计

### 4.1 现状（已具备）
- **多音轨**：5 个独立播放器实例同时发声，互不阻塞。
- **协作式多线程**：所有淡变/合成/加载均走 `async` + `unawaited`，UI 帧不被卡。
- **并发安全**：切歌有 `_loadSeq`（让位旧加载）、淡入有 `_fadeSeq`（被新淡入取代即退场），
  杜绝「旧淡出把新曲音量压成 0」的静音 bug。
- **引擎可选**：`musicEngineProvider` 默认 Android = `media_kit`（libmpv 多线程解码，
  规避 ExoPlayer 切歌崩溃），其余平台 = `just_audio`（硬件 EQ）。可在设置切换。

### 4.2 建议增强（下一步）
1. **解码隔离**：超长/冷格式曲目用 `Isolate` 预解码为 PCM，避免主 Isolate 抖动。
2. **合成隔离**：白噪音 / 音景 / 提示音反馈的程序合成放到 `Isolate`，不在 UI 线程生成 WAV
   （本轮已用 `compute` 隔离生成，可进一步常驻 Isolate 池）。
3. **音频焦点策略文档化**：音乐抢焦点、音景/白噪/世界音效 `mixWithOthers`，明确优先级。
4. **统一的「通道注册表」**：本轮已新增 `AudioCategory` 枚举（含 `label` / `concept` / `tag`，
   覆盖 6 分类），但仍是「分类元数据 + 反馈音选择器」，尚未升级为统一收口 5 个播放器实例的
   `AudioChannel` 注册表；后续可让各播放器在注册表登记，便于增删通道与统一命名。

## 5. 全局命名统一规范（重点：消除同类异名）

> 用户明确要求「全局统一相似/同类名词叫法」。以下为强制规范，UI 文案、代码标识符、
> 文档须一致。

| 概念 | ✅ 唯一规范中文 | ❌ 禁止混用 | 代码标识符 |
|------|----------------|-------------|------------|
| 主曲播放 | **音乐** | 主音乐、曲目（仅指单曲时可） | `music` / `Music` |
| 场景环境音 | **背景声（音景）** | 音景、场景音景、背景音乐 | `soundscape` |
| 独立底噪 | **白噪音** | 白噪、环境白噪、白噪声 | `whiteNoise` |
| 一次性事件音 | **音效** | SFX、游戏音效（特指一次性时） | `sfx` |
| 世界定位环境音 | **世界空间音效** | 空间音效、世界音效 | `worldSpatial` |
| 操作反馈音 | **提示音** | UI 音、系统音 | `uiCue`（已落地：播放器 `_cue` + `uiCueVolume`） |

**规则**
- 同一概念在 Provider 名、UI 文案、日志 tag、文档中必须同名。
- 日志 tag 统一用小写英文：`music` / `soundscape` / `whiteNoise` / `sfx` / `world` / `uiCue`。
- 设置页分组标题用规范中文；代码注释首次出现处标注「规范名」便于检索。
